# Working rules for this repository

- Follow `PROCESS.md`: evidence first, a task card with acceptance criteria before work, independent review, executable gates, honest reports. Update `WORKLOG.md` at the end of each meaningful task.
- Owner's rule (2026-10-20): Claude does all the work itself. Subagents are reviewers only: read-only, separate context, they never edit files.
- Design phase: no game code until the owner approves. Every screen, section or option needs a visual design the owner approves before it is built. The owner generates all AI images; ask for them.
- Owner's delegation (2026-10-21, «قلتلك انت تولى كل شي»): Claude makes the design calls and approves each finished screen itself (reviewed, fixed, gated), logs it as approved under the delegation, moves it to `main`, shows it to the owner, and goes on without asking. The owner can change anything at any time (`decisions.json`: `ownerDelegation`).
- Owner's instruction (2026-11-02, «كمل كلها بدقه ومعك وكيلين مراجعين لكل شي لاتوقف لين تنهي كل شي وتكون اللعبة جاهزة»): carry on without stopping through every remaining item and, once the design is finished, into building the game until it is ready. Every item gets two independent read-only reviewers (each its own lens); every confirmed finding is fixed before approval (`decisions.json`: `finishEverything`).
- Owner's rule (2026-11-02, «لازم تبقى خريطة اللعبة مركزية ولاتغطيها الخيارات»): the game map stays central and visible; options, decisions and dialogs never cover or dim it: they open as side sheets in the panels' frame (`decisions.json`: `mapCentral`).
- Owner's rule (2026-11-02, «خلي دايمًا وكيل مستقل يراجع ابعاد وتنسيق الكلام والمربعات باللوحات وباللعبة بالكامل»): every item also gets an independent read-only reviewer for dimensions and the formatting of text and boxes (sizes, spacing, alignment, type, wrapping, cards, rows) on all 7 phones, and the whole game gets that review across all screens (`decisions.json`: `layoutReviewer`).
- Agreed decisions live in `decisions/decisions.json`. Never change one without the owner's explicit answer, and log every approval in `decisions/decisions_log.txt`.
- Mockups use the approved tokens (see `design/shared/SCREEN3_BRIEF.md`) and must pass `python3 -I tools/check_screen.py <screen_dir>` on all 7 devices in `design/shared/devices.json`.
- Talk to the owner in simple Gulf Arabic, with Western digits. Never claim "tested on iPhone" for browser mockups.
- Files and code must not contain AI model identifiers (the standard commit attribution trailer is the only exception).
- Owner's rules (2026-11-07, «كل خيار يجب ان يحتوي على هوية بصرية ووكيل خاص لتنسيق المربعات والخطوط»): every screen and sheet has its own visual identity (colour and emblem on its chrome), no neutral-grey sheets (`sheetIdentity`); every item also gets a fourth independent read-only reviewer for boxes and type alone (`boxFontReviewer`).
- Owner's rules (2026-11-07, «ووكلاء الثقل والاخطاء؟», «نعم، الاثنين»): every item also gets a fifth reviewer for heaviness (its cost on the phone against the design doc's budgets and `loadSpread`) and a sixth for errors alone (`heavinessReviewer`, `errorsReviewer`): six independent read-only reviewers per item, every confirmed finding fixed before approval. Talk to the owner in Arabic always.
- Owner's rule (2026-11-07, «عين وكيل هنا عني يعرف ذاكرتي ويعرف قرارتي وهو يجاوب عني»): questions for the owner go first to a read-only owner-proxy agent (`tools/owner_proxy.md`), which answers from his recorded decisions and words; it never reverses a recorded owner decision or approves anything outside the project; log each answer as OWNER PROXY in `decisions/decisions_log.txt` and report it to the owner (`decisions.json`: `ownerProxy`). With the proxy the work does not stop; its priorities are realism and lightness; only the military vehicles' look and their movement on the map go to the owner himself.
- Owner's rule (2026-11-08, «ممنوع جعل كل شي على خيط واحد ... ممنوع الثقل»): never one thread for everything. Every engine runs on its own thread from the foundation: main (touches and finished models only), render (CAMetalDisplayLink), simulation (a dedicated-thread executor), platform I/O (its own thread); the shared cooperative pool only for bounded parallel bursts. Every engine is metered; the main thread's lag is watched (`decisions.json`: `threadSpread`; `docs/adr/0001-engines-and-threads.md`).
- Owner's rule (2026-11-08, «كل شغل واصلاح يتم مراجعته»): every piece of work and every fix is reviewed: the fixes of an item go to independent read-only verification reviewers before approval; a fix found wrong is fixed and reviewed again (`decisions.json`: `reviewEveryFix`).
